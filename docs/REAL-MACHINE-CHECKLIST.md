# DeskBox 真机验收清单（v1，基于 main `e69e956`）

在自己的 Windows 10/11 电脑上逐项操作，每项勾「通过 / 不通过」，不通过请截图并记下时间。
数据库与日志：`%LOCALAPPDATA%\DeskBox`；收纳库：`%USERPROFILE%\DeskBox\Vault`。

## A. 启动与单实例
**先拿到预览版程序（不用装开发环境）：**
1. 打开仓库的 Actions 页面，选 CI 里 main 分支最新一次绿色的运行，拉到页面底部「Artifacts」，下载 `DeskBox-preview-<提交号>-win-x64`（下载下来是一个 zip，提交号就是这次构建对应的 main 提交，保留 30 天）。
2. 把这个 zip 解压一次到任意文件夹，双击里面的 `DeskBox.exe` 运行。程序自带运行环境，不用另装 .NET。
3. 这个程序没有签名，第一次运行会弹出蓝色的「Windows 已保护你的电脑」。点「更多信息」，再点「仍要运行」即可，这不是程序坏了。
4. 预览版和以后的正式版用同一个数据目录：数据库和日志在 `%LOCALAPPDATA%\DeskBox`，收纳库在 `%USERPROFILE%\DeskBox\Vault`。数据库迁移只往前走，所以测完以后装正式版不会冲突；但不能降级，**不要用旧的 zip 打开新库**。

- [ ] A1 首次启动：自动建 `%LOCALAPPDATA%\DeskBox\deskbox.db` 和 `%USERPROFILE%\DeskBox\Vault`，无报错。
- [ ] A2 连续双击启动两次：只留一个实例，任务管理器里只有一个 DeskBox 进程，第二次不报错退出。
- [ ] A3 关闭后再启动：方框位置、大小与关闭前一致。

## B. 桌面嵌入
- [ ] B1 正常开机自启：方框嵌在桌面图标层，`Win+D` 显示桌面后方框仍在。
- [ ] B2 资源管理器未起来时（开机极早启动，或任务管理器结束 explorer.exe 后启动 DeskBox）：方框降级显示（置底窗口），不崩溃。
- [ ] B3 任务管理器重启 explorer.exe：几秒内方框自动嵌回桌面（收到 `TaskbarCreated`）。
- [ ] B4 Windows 11 24H2 / 25H2（`winver` 显示 24H2 或 25H2，build 26100 / 26200 起）：启动后几秒内桌面上能看到方框，能点到；`Win+D` 后仍在。看不到方框即不通过（P0，PR #24）。
- [ ] B5 启动一次后，`%LOCALAPPDATA%\DeskBox\logs\deskbox.log` 存在，里面有 `Embed fence=` 行，带 `os=[build 26xxx.xxx, DisplayVersion 24H2/25H2]`、`layering=`、`parent=[...]`、`path=`；另有 `DesktopScanStarted` / `DesktopScanCompleted`（或只读时的 `DesktopScanSkipped`）。反馈问题时把这个文件发回来（只含文件名和数量，贴公开 issue 前注意文件名隐私）。
- [ ] B6 兼容显示：若 B4 方框显示为普通置底窗口（日志里 `path=Fallback`），鼠标悬停托盘图标，提示为「DeskBox：桌面嵌入不可用，已切换为兼容显示」；不弹窗、不进只读模式，收纳和移动照常可用；点方框后它不会盖到其他窗口上面。
- [ ] B7 24H2 / 25H2 上任务管理器重启 explorer.exe：几秒内方框重新嵌回桌面（日志出现新的 `Embed ... path=Embedded`，`parent=` 里的 Progman 句柄与重启前不同），托盘图标重新出现；之前若是兼容显示，托盘提示恢复为「DeskBox」。

## C. 多显示器
- [ ] C1 方框放在副屏，拔掉副屏：方框临时出现在主屏工作区内，完整可见。
- [ ] C2 不移动方框，接回副屏：方框回到副屏原位置（临时挪主屏不落库）。
- [ ] C3 100% / 150% / 200% 缩放下拖动方框后重启：位置不漂移。

## D. 收纳库（同盘 / 跨盘）
- [ ] D1 桌面与 `%USERPROFILE%` 同盘（通常都是 C:）：把桌面文件收进收纳库成功，文件出现在 Vault 目录，桌面上消失。
- [ ] D2 桌面被重定向到其他盘（如 D:\Desktop）或用 D: 盘文件测试：提示「跨盘跳过」（CrossVolume），原文件不动、Vault 里没有副本。
- [ ] D3 公共桌面（`C:\Users\Public\Desktop`）上的快捷方式：跳过并提示需要管理员，不移动。
- [ ] D4 OneDrive 仅云端文件：跳过（CloudOnly），不触发下载。

## E. 异常与恢复
- [ ] E1 收纳过程中用任务管理器强杀 DeskBox，再启动：能正常启动，无文件丢失或重复（同一文件只在桌面或 Vault 其中一处）。
- [ ] E2 恢复失败时进入只读模式：有提示，方框照常显示，但不会移动文件。
- [ ] E3 退出 DeskBox，先把 LocalAppData 里的数据库文件复制一份备份；确认暂存方框是空的（里面没有文件）再操作，否则不要做这一项。用 DB Browser 等工具删掉 `is_staging=1` 的方框，再重新启动：暂存方框自动补建，只有一个，日志里有 `StagingFenceRecreated` 警告。

## F. 方框界面（TDD §4.7，PR #18）
- [ ] F1 右键方框：真弹出菜单（非平铺图），菜单项齐全；只读模式下「移到其他方框 / 从方框移除 / 移入收纳库 / 删除方框」置灰，悬停有原因提示。
- [ ] F2 拖标题栏移动方框：拖动流畅，松手后重启位置不变；拖到屏幕外会被夹回可见区。
- [ ] F3 拖边角改大小：宽高不能小于 120 DIP，松手后重启大小不变。
- [ ] F4 方框间拖放文件：目标方框有投放高亮；松手后归属改变，磁盘上文件位置不变（资源管理器核对路径）。
- [ ] F5 拖动中按 Esc：回到原位；嵌入桌面（WorkerW）状态下 Esc 也生效，焦点不被桌面抢走，不残留拖动状态。
- [ ] F6 暂存方框不能删；公共桌面项「移入收纳库」不可用并有原因提示。
- [ ] F7 已开 DeskBox 时再次启动：已开窗口恢复并置前，不出现第二个进程。
- [ ] F8 删除有文件的方框：弹出一次确认框，写明「N 个文件会移到暂存方框，磁盘上的文件不动」；默认选中「取消」，直接回车或按 Esc 都不删除。点确定后，文件出现在暂存方框末尾，磁盘路径不变。空方框删除时不弹框。
